## ADR-001 选定混合架构

```
[决策编号] ADR-001
[决策标题] 选定混合架构（管道-过滤器 + 分层 + 横切）
[决策状态] 已接受
[决策内容] V1.1 采用混合架构：核心主链 URL→下载→缓存→转写→LLM→笔记→落盘 走管道-过滤器，CLI 入口与并发调度走分层，错误处理与日志走横切。
[决策理由]
  1. 业务流以数据处理为主，管道-过滤器天然契合（[SA:BP-002~BP-010] 顺序固定）
  2. 错误处理（BP-012）与日志（BP-016）天然横切所有模块，独立为 M-010/M-011
  3. CLI 多子命令 + 并发调度需分层隔离（[SA:BP-001/BP-011]）
  4. V2.0 演进路径需扩展点（EP-002 章节降级策略）走横切 [TD推断:基于演进路线 V-002/V-003]
[拒绝的替代方案]
  - ADR-001-A 纯分层架构: DTO 维护成本高，管道语义丢失 → 拒绝
  - ADR-001-B 微服务架构: V1.1 单机假设被打破，且引入网络延迟 → 拒绝
  - ADR-001-C 纯事件驱动: BP 顺序固定，事件总线反而增加复杂度 → 拒绝
[影响范围] 全部 12 模块
[相关ADR] ADR-002（模块拆分）, ADR-005（错误处理横切）
[来源标注] [TD推断:基于 AC-方案对比]
```

  - ADR-002-A 保留 M-001 内: 接口数超限（5 个）+ 内聚度从 6/6 降至 5/6 → 拒绝
[影响范围] M-001（减少依赖）, M-012（新增）
[相关ADR] ADR-001
[来源标注] [TD推断:基于 MP 内聚度自检]
```

## ADR-004 缓存采用 sqlite WAL

```
[决策编号] ADR-004
[决策标题] 缓存存储选型 sqlite + WAL 模式
[决策状态] 已接受
[决策内容] M-004 缓存使用 sqlite 3.x + WAL 模式，路径 ~/.cache/research-tool/cache.db。
[决策理由]
  1. V1.1 单机假设下 sqlite 足够（10k 条目 / 5GB 上限）
  2. WAL 模式支持 3 并发读 + 1 写
  3. asyncio.Lock 串行化写，避免 V1.1 阶段引入分布式锁复杂度
  4. 零运维成本（用户无感知）
[拒绝的替代方案]
  - ADR-004-A Redis: 单机假设下过度设计 + 引入额外进程 → 拒绝
  - ADR-004-B 文件系统 JSON: 查询效率低，hit_count 累加需读改写 → 拒绝
  - ADR-004-C LevelDB/RocksDB: 需额外依赖，V1.1 不必要 → 拒绝
[影响范围] M-004
[相关ADR] ADR-007（V2.0 迁移路径）
[来源标注] [SA:BP-004/DE-004/BR-026] [调研:S-102]
```

## ADR-005 字段名前缀校验放在 M-006 而非 M-007

```

[决策状态] 已接受
[决策内容] BP-006 步骤 6 的字段名前缀校验（video_ 强制）放在 M-006.IF-014，而非 M-007。

[拒绝的替代方案]
  - ADR-005-A M-007 校验: M-006 输出已污染，需在 M-007 端重新解析 → 拒绝
  - ADR-005-A M-001 校验: M-001 不感知 LLM 输出细节 → 拒绝
[影响范围] M-006, M-007（移除校验逻辑）
[相关ADR] ADR-001
[来源标注] [SA:BR-003/BR-025] [SA洞察#2] [CE-006]

## ADR-006 并发上限 3 + URL 上限 10

```
[决策编号] ADR-006
[决策标题] 并发上限 3 + URL 上限 10
[决策状态] 已接受
[决策内容] BP-011 固定并发上限 3（asyncio.Semaphore(3)），单次入参 URL 数量上限 10（超出仅取前 10 + 提示）。
[决策理由]
  1. [PRD:F-008.AC-1] 3 个 30 分钟视频 ≤ 12 分钟（性能约束）
  2. [PRD:F-008 边界] URL > 10 队列上限
  3. 3 并发 × medium 档 = 6-12GB RAM（资源约束 BR-007）
  4. M-012.IF-030 资源探测可自适应降到 2 并发
[拒绝的替代方案]
  - ADR-006-A 并发 5: 资源不足（5×medium = 10-20GB），易 OOM → 拒绝
  - ADR-006-B URL 上限 50: 长时间队列影响用户体验 → 拒绝
[影响范围] M-012
[相关ADR] ADR-002
[来源标注] [SA:BP-011/BR-012] [PRD:F-008.AC-1]
```

## ADR-007 V2.0 缓存迁移 Redis 路径

```
[决策编号] ADR-007
[决策标题] V2.0 缓存从 sqlite 迁移到 Redis（双写策略）
[决策状态] 已接受
[决策内容] V2.0 阶段将 M-004 内部 sqlite 实现替换为 Redis + 云端，双写 14 天后切读，关闭 sqlite。
[决策理由]
  1. V2.0 触发条件包含"多设备同步需求"（单机假设打破）
  2. V2.0 候选方案对比中 Redis 分布式锁支持 > sqlite
  3. 双写策略保证迁移期数据一致性
  4. 缓存接口（IF-009/IF-010/IF-011）保持稳定，下游无感
[拒绝的替代方案]
  - ADR-007-A 直接切 Redis: 迁移期无 rollback 保障 → 拒绝
  - ADR-007-A 保留 sqlite 主存 + Redis 缓存: 复杂度高 → 拒绝
[影响范围] M-004 实现（接口不变）
[相关ADR] ADR-004
[来源标注] [TD推断:基于 ER V-003]
```
