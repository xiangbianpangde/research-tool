## V-003 V2.0（中长期演进）

```
[演进阶段] V-003 V2.0
[触发条件] 以下任一指标触发：
  - 单用户日均视频摄入 > 10（单机 sqlite 容量瓶颈）
  - 多设备同步需求出现（V1.1 单机假设打破）
  - Whisper medium 推理需 GPU 加速
[新增模块]
  - M-014 GPU Whisper 推理服务（独立 REST 服务，端口 9001）
  - M-015 远程缓存适配器（替换 M-004 内部 sqlite 为 Redis + 云端）
  - M-016 LLM 代理（统一鉴权 + 限流 + 多供应商路由）
[废弃模块]
  - M-005 内置 faster-whisper 推理（保留转写调度逻辑，调用 M-014）
  - M-004 内部 sqlite 实现（保留缓存接口，实现切换到 M-015）
[迁移策略] 双写
  - 缓存: V2.0 期间 sqlite + Redis 双写 14 天 → 切读 Redis → 关闭 sqlite
  - Whisper: GPU 服务可选，未部署时回退本地推理
[回滚策略]
  - 触发: GPU 服务 P99 延迟 > 10s / Redis 不可用率 > 1%
  - 步骤: 配置开关 → 关闭 M-014/M-015 → 回退 M-005/M-004 内置实现
  - 数据一致性: 双写期间数据双向同步，回滚后无数据丢失
  - 预计回滚时间: < 10 分钟（开关级）
[风险等级] 高（涉及数据迁移 + GPU 资源）
[依赖] 用户硬件升级 / 云端预算
[来源标注] [TD推断:基于单机架构容量上限 + 性能瓶颈预判]
```

## V-004 V2.5（远期演进）

```
[演进阶段] V-004 V2.5
[触发条件] V2.0 稳定运行 6 个月后：
  - 需要支持更多视频源（抖音/小红书/快手）
  - 出现多用户协作需求
  - LLM 成本占比 > 总成本 30%
[新增模块]
  - M-017 多平台下载器接口（抽象 BaseDownloader，支持插件式接入新平台）
  - M-018 多租户隔离层（知识树分用户/团队）
  - M-019 LLM 缓存层（基于 Embedding 的语义缓存，降低重复转写稿的 LLM 成本）
[废弃模块]
  - M-003 bilibili/youtube 硬编码实现（替换为 M-017 + bilibili/youtube 插件）
[迁移策略] 蓝绿
  - 旧版本继续运行 → 新版本部署独立 namespace → 数据同步 → 切流量 → 旧版本停机
[回滚策略]
  - 触发: 蓝绿环境错误率差异 > 2% / 多租户数据隔离漏洞
  - 步骤: DNS 切回旧版本 → 旧版本恢复流量 → 新版本环境保留排障
  - 数据一致性: 同步期数据最终一致，回滚后已同步数据保留
  - 预计回滚时间: < 5 分钟（DNS 级）
[风险等级] 高（架构大改）
[依赖] V2.0 稳定 + 商业化决策
[来源标注] [TD推断:基于 V2.0 反馈 + 商业化路径]
```
