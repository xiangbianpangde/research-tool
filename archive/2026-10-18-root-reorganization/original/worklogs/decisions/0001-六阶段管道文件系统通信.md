# ADR 0001: 六阶段管道 + 文件系统通信

**日期**: 2026-05  
**状态**: 已采纳  
**决策者**: 项目架构设计

## 背景

调研工具的核心流程包括搜索、清洗、抽取、组织、报告等多个步骤，需要支持中断恢复、独立调试、增量重跑。

## 决策

采用六阶段管道架构（Collect → Deepen → Clean → Extract → Organize → Report），每个 Stage 仅通过文件系统通信：
- 输入：读取上一阶段的输出目录
- 输出：写入本阶段的产物目录

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 文件系统通信（采纳） | 可中断恢复、独立重跑、可检查中间产物 | 无事务保证、磁盘 I/O 开销 |
| 内存管道 | 速度快 | 无法中断恢复、内存压力大、调试困难 |
| 消息队列 | 分布式友好 | 过度设计，增加运维复杂度 |

## 影响

- 每个 Stage 输入/输出均为文件，可独立开发和测试
- `--resume` 默认启用：已完成阶段自动跳过
- 中间产物可被用户直接查看和修改
