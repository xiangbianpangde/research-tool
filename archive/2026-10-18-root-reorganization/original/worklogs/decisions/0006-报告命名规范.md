# ADR 0006: 报告命名规范

> **日期**: 2026-07-21
> **状态**: 已采纳
> **决策者**: Phase 8 汇总（基于 17 份产出物命名一致性回顾）

## 背景

`project_management/reports/` 下 8 份审核报告 + `worklogs/` 下 5 份日志，命名风格混杂：
- 部分用 `YYYY-MM-DD_主题.md`
- 部分用 `主题.md`（无日期）
- 部分用 `01-architecture_xxx.md`（序号 + 中文）

不一致的命名降低可检索性。

## 决策

统一规则：

| 文件类型 | 命名规范 | 例子 |
|---------|---------|------|
| 审核报告 | `<主题>.md`（无日期） | `project_overview.md` |
| 收束报告 | `收束报告-vX.Y.md` | `收束报告-v0.1.1.md` |
| 阶段汇总 | `YYYY-MM_phase-N-summary.md` | `2026-07_phase-3-summary.md` |
| 工作日志 | `YYYY-MM-DD_<简短描述>.md` | `2026-07-21_audit-kickoff.md` |
| 健康检查留痕 | `YYYY-MM-DD-llm-healthcheck-source-patch-attempt.md` | （已有样本） |
| ADR | `NNNN-<主题>.md`（4 位零填充） | `0001-六阶段管道文件系统通信.md` |
| HTML 报告 | `<主题>.html`（无日期） | `final_report.html` |

与 devguard 风格保持一致（`docs/reports/YYYY-MM-DD_<project>_<topic>_报告类型.html`）。

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 统一规则（采纳） | 可检索性高 | 历史报告需保留原名（不重命名） |
| 完全自由 | 灵活 | 检索难 |
| 数字前缀（01-/02-） | 阅读顺序明确 | 重命名工作量大 |

## 影响

- `project_management/reports/` 全部按主题命名（无日期）
- `worklogs/` 按 `YYYY-MM-DD_主题.md`
- ADR 按 `NNNN-主题.md`（4 位零填充）
- 未来新报告/工作日志必须遵循此规范

## 后果

- 旧文件保留原名（避免破坏 git history）
- 新文件按规范创建
- 命名不一致时（既有文件 vs 规范），以既有文件为准，不强制重命名
