# ADR 0005: 创新点实验设计模板

> **日期**: 2026-07-21
> **状态**: 已采纳
> **决策者**: Phase 6 审核（基于 9 创新点验证结果）

## 背景

research-tool 6 阶段管道 + 反向传播、实体拆分去锚、SSRF guard、Expert Registry、Provider-agnostic LLM 等 9 个创新点，在没有"诚实性验证框架"前，容易演变为自吹自擂。

## 决策

每个创新点的 `innovation/<name>.md` 包含 5 字段：

```markdown
# 创新描述        （≤ 100 字）
# 技术原理        （≤ 200 字）
# 为什么创新      （对比已有方案；引用 1-2 个公开方案）
# 对比方案表格    （≤ 3 行）
# 实验设计        （baseline + metric + dataset + ablation + setup）
```

每个实验的 `experiments/<name>.md` 包含：

```markdown
# Baseline    （至少 2 个对照：B1 + B2）
# Metric      （≥ 2 个量化指标）
# Dataset     （来源 + 规模 + 是否可公开）
# Ablation    （≥ 4 个开关：A0/A1/A2/A3）
# Setup       （机器 + 数据 + 状态）
```

`validation_report.md` 强制诚实性章节：

```markdown
# VERIFIED            （完全跑通）
# PARTIALLY VERIFIED  （部分跑通 + 标注 UNVERIFIED 子项）
# UNVERIFIED          （标注"无法验证原因"）
```

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 5 字段模板（采纳） | 强制诚实性；可复用 | 文件数量多 |
| 自由叙述 | 灵活 | 易演变为自吹自擂 |
| 学术论文格式 | 严谨 | 过度形式化 |

## 影响

- Phase 6 审核产出 9 创新点：3 VERIFIED + 6 UNVERIFIED（诚实标注）
- 实验失败原因分类（数据/资源/已可执行但未跑）便于后续补做
- 创新点 3/5/7 已从 PARTIALLY VERIFIED 升级到 VERIFIED（2026-07-21 黑盒实验通过）

## 后果

- 后续创新点 brainstorm 必须按 5 字段模板记录
- 验收新创新点的最低门槛 = PARTIALLY VERIFIED（至少 baseline + 1 metric 跑通）
