§0 概览

research-tool

给定一个主题或一批 PDF，自动完成搜索→清洗→知识树→调研报告。

一句话定位

Python 核心引擎 + 多接口层（CLI / WebUI / Python SDK）的自动化调研工具。 五阶段管道，Stage 之间仅通过文件系统通信，可中断恢复、可独立调试。

技术栈

Python 3.11+ Pydantic v2 Typer Rich Gradio httpx Crawl4AI MinerU DuckDuckGo arxiv Tavily OpenAI API

设计原则

  • 文件系统通信：Stage 之间零直接调用，只读写约定的目录结构（raw/→clean/→extracted/→tree/）
  • 可中断恢复：resume=true 时自动检测已有输出，跳过已完成 Stage
  • Extractor 可选：不安装 LLM 也能跑（跳过抽取，Organizer 直接消费 clean/）
  • 独立调试：每个 Stage 可通过 CLI 单独执行
  • LLM 抽象：统一 LLMClient 抽象，支持 4 种 Provider
§2 职责

分层职责详解

L5 接口层 · cli.py / webui.py / __init__.py

CLI：基于 Typer，薄封装。5 个子命令 + 1 个 ui 命令。Rich 美化输出，UTF-8 重编码防 GBK 崩溃。

WebUI：Gradio 双栏布局。左栏输入，右栏流式进度+报告渲染。后台起线程跑管道，queue.Queue 传事件。

SDK：暴露 research()、quick_collect() 高阶函数，直接调 ResearchPipeline。

L4 编排层 · pipeline.py

ResearchPipeline：串行编排 5 个 Stage，支持 stream()（流式事件）和 run()（批量）。内部判断 resume 跳过。Extractor 可选跳过。PDF 模式切换采集源为 PdfIngestor。

L3 阶段层 · stages/

Collector：搜索（多轮×多引擎）→ URL 去重 → 并行抓取 → 写 raw/*.md

Cleaner：纯本地去 HTML 标签/导航/广告/短行 → 写 clean/*.md

Extractor：LLM 抽取实体/关系/三元组，分块并发，自动归纳 Schema

Organizer：map-reduce：逐篇摘要→规划节点→并行写 N1~N7 → 00-主表

Reporter：LLM 合成最终报告，4 种 style，Markdown/HTML

L2 服务层

LLM：抽象基类 → OpenAI / Anthropic / Mock。统一 chat/chat_structured/stream。

搜索：SearchBackend 抽象 → DDG / Arxiv / Tavily。工厂 + CachingBackend 装饰器。

抓取：Fetcher — 主路径 Crawl4AI，回退 httpx。PDF 自动走 MinerU。

L1 基础设施

config.py：YAML → ${VAR} 替换 → 环境变量 → 深度合并 → Pydantic 校验。无配置时自动补 API Key。

models.py：所有 Pydantic 模型。配置模型 + 结果模型 + 事件模型。

errors.py：统一异常体系，ResearchToolError + 5 个子类。

§3 流程

运行流程 · 全链路

从 start.bat 到 report.md，共 9 步

① start.bat→ ② .env 加载→ ③ 菜单选择→ ④ CLI/UI 入口→ ⑤ config 装载→ ⑥ Pipeline.stream()→ ⑦ 5 Stage 串行→ ⑧ 文件系统读写→ ⑨ report.md

从 start.bat 到 report.md 的完整全链路

1 start.bat → 检测 .venv → 激活 → 加载 .env → 显示菜单
2 用户选「2.Web research」→ 输入 topic + rounds
3 start.bat 拼装: research run "topic" -s web -r 2 --llm-expand --skip extract
4 cli.py: run() → load_config() 读 config.yaml + 环境变量 → PipelineConfig
5 cli.py: ResearchPipeline(config).run(topic) 执行
6 pipeline.py: stream() → 遍历 stages，每个先检查 resume 跳过
7 Stage 1: Collector.run() → search_only() 多轮 × 多引擎 → Fetcher 并行抓取 → 写 raw/*.md + sources.json
8 Stage 2: Cleaner.process() → 遍历 raw/*.md → clean_text() 去噪 → 写 clean/*.md + quality.json
9 Stage 3: extractor.enabled=false → 跳过
10 Stage 4: Organizer.run() → 逐篇 LLM 摘要 → LLM 规划节点 → 并行写 N*.md → 主表
11 Stage 5: Reporter.run() → 读 tree/* → LLM 合成 → 写 report.md
12 cli.py: _log("调研完成 → report.md")

WebUI 模式

Gradio 环境。用户点击「开始」→ run_web() 构造 override → load_config() → daemon 线程跑 Pipeline → queue.Queue 传 StageEvent → UI 右栏流式更新。完成后渲染报告。

PDF 模式

--pdf-dir 设置时，Collect 不走搜索，调 PdfIngestor.run()：收集 PDF → 逐个 MinerU 解析 → (可选 LLM 翻译) → 写 raw/*.md。后续同管道。

核心数据契约

  • 所有 Stage 通过文件系统通信，不通过内存变量
  • 可 Ctrl+C 中断后 resume 恢复
  • 可手动编辑中间 .md，重新跑后续阶段
  • 可复制别人产出的 raw/，直接跑 clean→organize→report
  • 目录结构固定：{topic}/{raw,clean,extracted,tree}/
§5 调用

调用链 · 代码执行顺序

1 cli.py: run(topic, source=['web','arxiv'], ...)
2 ├─ load_config() → config.py: YAML + env + overrides → PipelineConfig
3 ├─ ResearchPipeline(config).run(topic)
4 │ └─ stream(topic): async for event in ...

7 │ │ ├─ search_only(): 多轮×多引擎搜索 → URL 去重

9 │ ├─ stage="clean" → Cleaner.process(raw_dir)

11 │ ├─ stage="extract" → 跳过 (extractor.enabled=false)
12 │ ├─ stage="organize" → Organizer.run(clean_dir, llm)
13 │ │ ├─ 逐篇 LLM 摘要 (map)

§6 文件

核心文件精讲

cli.py · CLI 入口

作用：Typer 命令解析，薄调用层。11 个子命令：run/collect/clean/extract/organize/report/ingest-pdf/status/config/ui/translate。

核心函数：run() 接受 topic/source/depth/rounds 等 → 构造 Config → ResearchPipeline.run()。each stage 有独立子命令（如 clean() 直接调 Cleaner.process()）。

逻辑：UTF-8 stdout/stderr 重编码防 GBK 崩溃；_state 维护全局；_make_llm() 懒创建 LLMClient。

pipeline.py · 编排引擎

ResearchPipeline：五阶段状态机。stream() 异步迭代 StageEvent；run() 遍历到结束。_exec() 分发到具体 Stage。resume 检测用 has_output() 看目录是否有文件。PDF 模式切换为 PdfIngestor。Extractor 可选跳过。

stages/collector.py · 采集

search_only()：多轮×多引擎，URL 去重，返回 SearchHit。支持 LLM 动态生成查询（优先于模板）。

run()：search_only → Fetcher.fetch() 并发（Semaphore） → depth=3 追二级链接 → 垃圾过滤 (min_doc_chars) → 写 raw/XX-domain.md + sources.json。

算法：多轮查询扩展（模板或 LLM），保序去重，并发 Semaphore 控制抓取。

stages/cleaner.py · 清洗

clean_text(text) → str：拆分 meta → 检测二进制 (%PDF) → 去 HTML 标签 → 去广告关键词 → 去导航块（连续≥3 行且 70% <40 字符）→ 定位正文起点（首个≥120 字符行）→ 截断尾部 (References) → 合并空行。

process(input_dir) → CleanResult：遍历 raw/*.md → 每个调 clean_text → 质量评分 → 写 clean/*.md + quality.json。

stages/extractor.py · 信息抽取

run(input_dir, llm) → ExtractResult：读 clean/*.md → 分块 (4000/200 overlap) → Semaphore(4) 并发 LLM chat_structured → 去重聚合 → 自动归纳 Schema → 写 entities.json/relations.json/triples.json/schema.json。

关键：entity_types 为 null → 自动归纳。单块失败不中断。去重用 (name_lower, type_lower) tuple。

stages/organizer.py · 知识树

run(input_dir, llm) → OrganizeResult：
① _load_clean_docs() 读 clean/*.md
② _summarize_all() 逐篇 LLM 摘要（分块→points 列表），每篇 ≤18 条要点
③ _plan_nodes() LLM 规划 4-7 个节点 + 主线
④ _node_body() asyncio.gather 并行写 N*.md (S1-S4 格式)
⑤ _main_table() 写 00-主表.md

算法：map-reduce。每个节点 S1=原始依据 S2=核心观点 S3=节点关系 S4=主线位置。标注来源可追溯。

stages/reporter.py · 报告

run(tree_dir, llm, topic) → ReportResult：读 tree/00-主表.md + N*.md → LLM 按 style 合成 → (可选 HTML 渲染) → 写 report.md/html。

4 种 style：report (定义→背景→要素→争议→应用→总结)、feasibility (现状→方案→利弊→风险→建议)、review (脉络→流派→文献→趋势)、article (引言→论点→结论)。

关键：截断模型自行输出的不完整参考资料，代以 sources.json 生成的权威列表。自动附加日期/来源统计/词数。

config.py · 配置

YAML 加载 → ${VAR} 环境变量替换 → flatten 到 PipelineConfig → 环境变量覆盖 → secret 自动补齐 → 深度合并 overrides → Pydantic 校验。

查找顺序：--config > $RESEARCH_CONFIG > ./config.yaml > ~/.research/config.yaml。零配置启动自动从 $DEEPSEEK_API_KEY 补齐 api_key。

search/ · 搜索后端

get_backend() 工厂：构造后端 + 套 CachingBackend 装饰器。
DuckDuckGoBackend：免费免 Key，调 ddgs 库。
ArxivBackend：官方 API，delay=3s retry=5 + 进程级全局限速（asyncio.Lock）。
TavilyBackend：需 Key，稳定高质量。
CachingBackend：按 engine+query 哈希缓存，TTL=86400s。

llm/ · LLM 抽象

LLMClient：抽象基类。from_config() 工厂选实现。
OpenAILLMClient：覆盖 DeepSeek/Ollama。chat_structured 用 response_format=json_object。
AnthropicLLMClient：system prompt 约束 + 容错解析。
MockLLMClient：测试用，可注入固定返回/回调。

ingest/pdf.py · PDF 摄取

PdfIngestor.run(pdf_path, work_dir) → CollectResult：收集 PDF → 逐个同步调 mineru 子进程（避免显存竞争） → (可选 translate_markdown 翻译) → 写 raw/*.md + sources.json。

find_mineru() 探测路径。未安装时清晰报错含安装提示。

webui.py · Gradio 界面

build_ui()：双栏布局。左栏模式选择/主题/引擎/轮次/输出设置/LLM 设置。右栏进度日志 + 报告渲染 + 文件下载。

run_web()：构造 override → load_config() → 起 thread 跑 Pipeline → queue.Queue 传 StageEvent → 流式 UI 更新。

§9 算法

关键算法 / 设计决策

多轮搜索（方法论 1.1）

1-3 轮扩展：核心词 → 交叉/相关 → 应用/对比。中英文并行。可 LLM 动态生成。

并发控制

Semaphore 控抓取/LLM 并行。MinerU 逐个跑防显存竞争。

导航块检测

连续≥3 行且 70%<40 字符 → 导航。纯本地算法。

正文起点定位

跳过纯链接行，找到首个≥120 字符段落。纯本地。

Map-Reduce 知识树

先 map（逐篇摘要），再 reduce（合并证据→规划节点→并行写）。保证每篇都被读到。

文件系统通信

Stage 零直接调用。可中断、可编辑、可独立调试。

LLM 结构化容错

剥离 ```json 包裹。单块失败不中断整批。

CachingBackend

磁盘缓存按 engine+query 哈希。TTL=86400s。缓解限流。

arxiv 全局限速

asyncio.Lock + 进程时间戳 ≥3s。双重保护（client delay=3s retry=5）。

翻译分块并发

按段落 ≤3000 字符分块。Semaphore(8) 并发 LLM。单块失败留原文。

一句话总结

CORE · 核心价值

research-tool 是一个「从零散信息到结构化知识」的自动化管道引擎。

通过 Collect → Clean → Extract → Organize → Report 五阶段流水线，把一个主题或一批 PDF 自动转化为知识树（主表+N个节点）+ 调研报告。核心设计：文件系统隔离、可中断恢复、LLM 统一抽象、搜索后端可插拔。提供 CLI / WebUI / Python SDK 三种接口。适用于学术调研、行业研究、技术方案预研。
