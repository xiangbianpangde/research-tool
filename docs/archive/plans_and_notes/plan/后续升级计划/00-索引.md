## 三、关键决策摘要

1. **核心定位**：在 research-tool 中新增"视频摄入"能力，复用 BiliNote 的"下载+转写"模块，去除其消费侧（前端/DB/任务队列/截图），对接 research-tool 的"调研管道"（Collect→Clean→Extract→Organize→Report）。
2. **接入方式**：转写结果以标准 Markdown+YAML front matter 写入 `raw/`，作为 collect 阶段的替代路径，**下游零改动**。
3. **平台优先级**：B站、YouTube（一期 P0）；本地文件（一期 P1）；抖音/快手/小宇宙等二期 P2 评估。
4. **模型硬约束**：所有 agent 一律 `deepseek-v4-flash`（用户硬约束1）。
5. **集成边界（用户硬约束4）**：BiliNote 移植 = `downloader` + `transcriber`（约 60% 代码量）；research-tool 新建 = `video_ingestor` + `pipeline_adapter` + `cache_manager` + `cli_bindings`。
6. **交付物约束（用户硬约束2）**：本 workflow 是 `/plan-writing`，第⑦棒文件框架只产出"带注释的空文件骨架"，不写实现代码。
7. **系统模拟约束（用户硬约束3）**：第⑧棒必须真实串起"用户贴链接 → 跑管道 → 出报告"端到端示例。
