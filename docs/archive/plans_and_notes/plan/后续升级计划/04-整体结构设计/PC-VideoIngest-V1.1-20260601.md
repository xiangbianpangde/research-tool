## PC-001 30 分钟视频端到端延迟

```
[性能指标] 30 分钟视频端到端处理时间
[预估规模]
  - 当前目标: ≤ 8 分钟 [PRD:NF-001]
  - 转写（最大块）: ≤ 5 分钟（medium 档）[PRD:F-004.AC-1]
  - 下载: 1-2 分钟（1080p）
  - LLM 总结: 30-60 秒
  - 落盘 + 管道: 10-30 秒
[架构应对策略]
  - 转写: M-005 whisper medium + CPU 推理
  - LLM: M-006 HTTP 调用（含 fallback 切换）
  - 缓存: M-004 sqlite 命中时跳过转写/LLM
  - 并发: M-012 Semaphore(3) 限流
[瓶颈模块] M-005 转写（计算密集 + 内存密集）
[扩展方式]
  - 垂直: 升级 CPU 至 8 核 → 转写降至 3 分钟
  - 水平: V2.0 M-014 GPU Whisper 服务独立部署
[基准测试建议]
  - 测试数据集: 3 个 30 分钟 1080p 视频（标准普话 + 英文 + 粤语音频）
  - 测试场景: 1 并发 + 3 并发 + 5 并发
  - 测量指标: 下载时长 / 转写时长 / LLM 时长 / 端到端时长 / 内存峰值
  - 通过标准: 端到端 P95 ≤ 8 分钟
[风险] SR-004（内存瓶颈）
[来源标注] [PRD:NF-001/F-004.AC-1] [BR-018]
```

## PC-002 缓存命中率

```
[性能指标] 缓存命中率
[预估规模]
  - 当前目标: 同 URL 重复入参 ≤ 3s 返回 [PRD:F-009.AC-1/AC-E2E-03]
  - 预期命中率: 30-50%（首跑 + 重复入参混合）
  - YouTube 衰减: 24h 内 revalidate（BR-024）
[架构应对策略]
  - 缓存键: sha256(url) + etag/last_modified（双键 BR-004）
  - 存储: sqlite WAL 模式 + asyncio.Lock
  - 失效: ttl=30d（BR-026）/ YouTube 24h revalidate（BR-024）
[瓶颈模块] M-004 缓存（IO 密集，sqlite 读）
[扩展方式]
  - V1.2: 暴露缓存统计 CLI（命中率 + 命中 Top10）
  - V2.0: 迁移到 Redis（多设备共享 + 分布式锁）
[基准测试建议]
  - 测试数据集: 100 个视频（含 B 站 / YouTube 各 50）
  - 测试场景: 立即重复入参 / 24h 后重复 / 30 天后重复
  - 测量指标: 命中率 / 命中耗时 / 失效清理耗时
  - 通过标准: 立即重复 100% 命中且 ≤ 3s
[风险] SR-005（YouTube 衰减）/ SR-006（并发竞争）
[来源标注] [PRD:F-009.AC-1/AC-E2E-03] [BR-004/BR-019/BR-024/BR-026]
```

## PC-003 3 并发视频处理

```
[性能指标] 3 个 30 分钟视频并发处理
[预估规模]
  - 当前目标: ≤ 12 分钟（端到端）[PRD:F-008.AC-1]
  - 并发上限: 3（V1.1）/ URL 上限: 10
  - 资源: 8GB RAM 推荐 / 16GB 理想
[架构应对策略]
  - 编排: M-012 asyncio.Semaphore(3) + gather
  - 资源探测: M-012.IF-030 自适应降级到 2 并发
  - 转写: medium 档（3 并发需 6-12GB RAM）
  - 缓存: 3 任务可能同时 miss 同一视频 → 串行化写
[瓶颈模块] M-005（3×medium = 6-12GB）/ M-001（CLI 调度）
[扩展方式]
  - 短期: 资源紧张时降档 base/small（BR-007）
  - 中期: V2.0 GPU Whisper 服务
  - 长期: V2.5 多租户分集群
[基准测试建议]
  - 测试数据集: 3 个 30 分钟视频（混合平台）
  - 测试场景: 8GB RAM / 16GB RAM / 32GB RAM
  - 测量指标: 端到端时长 / OOM 次数 / 自动降级次数
  - 通过标准: 16GB RAM 下 3 并发 ≤ 12 分钟
[风险] SR-004（内存瓶颈）/ SR-006（缓存竞争）
[来源标注] [PRD:F-008.AC-1] [BR-012]
```

## PC-004 LLM 调用 token 预算

```
[性能指标] 单次 LLM 调用 token 预算
[预估规模]
  - 上限: 20k input / 4k output [PRD:F-005.AC-2/BR-002]
  - 典型: 8-15k 转写稿 + 4k prompt ≈ 12-20k input
  - 输出: 2-4k tokens（含章节 + 正文）
[架构应对策略]
  - M-006 输入校验: > 20k 截断 + 警告（不切分）
  - M-006 输出校验: > 4k 截断 + 警告
  - LLM 选型: Deepseek-v4-flash（NF-010）/ Qwen-turbo fallback（F-013）
[瓶颈模块] M-006 LLM（IO 密集，HTTP 1-5s）
[扩展方式]
  - 短期: 输入超 20k 截断（接受警告）
  - 中期: V2.0 M-019 Embedding 语义缓存（重复转写稿复用）
  - 长期: V2.5 多 LLM 供应商路由（成本优化）
[基准测试建议]
  - 测试数据集: 短 (5min) / 中 (30min) / 长 (120min) 视频转写稿
  - 测试场景: 单次调用 / fallback 切换
  - 测量指标: input_tokens / output_tokens / 调用时长 / 截断次数
  - 通过标准: 单次调用 ≤ 20k+4k，无切分
[风险] 章节连贯性损失（截断不切分是 PM 决策选项 A）
[来源标注] [PRD:F-005.AC-2/NF-010] [BR-002] [调研:S-008]
```

## PC-005 重试退避

```
[性能指标] 网络/IO 操作重试退避
[预估规模]
  - 重试上限: ≤ 2 次 [PRD:NF-009]
  - 退避策略: 指数退避 2^n（1s, 2s, 4s）
  - LLM 特殊: 3 次 5xx 后切换 fallback（不重试同模型）[BR-009]
[架构应对策略]
  - 通用: M-010 错误处理统一重试策略
  - LLM 特殊: M-006 内部 3 次 5xx → 切 qwen-turbo（仅 1 次切换）
  - 退避: 共享 retry_backoff 函数（2^n）
[瓶颈模块] M-010 / M-006
[扩展方式]
  - 短期: 当前实现已满足
  - 中期: V2.0 M-016 LLM 代理（统一重试 + 限流）
[基准测试建议]
  - 测试场景: 模拟 403/412/5xx 注入
  - 测量指标: 重试次数分布 / 总耗时 / 成功率
  - 通过标准: 任意操作重试 ≤ 2 次（LLM fallback 切换除外）
[风险] 网络抖动场景下重试耗时长
[来源标注] [PRD:NF-009] [BR-009/BR-015]
```
