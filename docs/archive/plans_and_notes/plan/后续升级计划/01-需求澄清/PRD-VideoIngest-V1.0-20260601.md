## 1. 需求背景与目标

### 1.1 背景

[用户原话] "让 research-tool 不仅能'搜文字'，还能'听视频'——用户粘贴一个 B站/YouTube 视频链接，系统自动把视频内容转写成结构化调研笔记，无缝接入现有知识树和报告生成流程。"

[用户原话] "建议集成 BiliNote 以复用其'听懂视频'能力。"

research-tool 当前（[PM推断:依据]基于 `产出物/00-索引.md` 与 `docs/research/参考资料/`）的"调研管道"由 Collect → Clean → Extract → Organize → Report 五阶段组成，数据源以纯文本/URL 爬取为主（[PM推断:依据]相关项目如 `crawl4ai`、`watercrawl` 均是网页爬取能力），缺乏"音视频源 → 文本 → 结构化笔记"的摄入路径。技术大会 talk、B站教程、YouTube 访谈等高价值内容源被排除在调研管道之外。

BiliNote（[用户原话] `C:\Users\yhn\BiliNote`）是开源 AI 视频笔记工具，已实现"多平台链接 → 音视频下载 → 字幕/Whisper 转写 → LLM 总结 → Markdown 笔记"完整链路，可直接复用其"听懂视频"核心能力（downloader + transcriber + LLM 后处理）。

### 1.2 核心目标

| 编号 | 目标 | 来源 |
|------|------|------|
| G-001 | 在 research-tool 新增视频摄入路径，CLI 支持 `research run --video-url <url>` 一键入管道 | [用户原话] |
| G-002 | 复用 BiliNote 的 downloader 与 transcriber 模块（约 60% 代码），去除其消费侧（前端/DB/任务队列/截图） | [用户原话] + [PM推断:依据]依据为集成成本与边界 |
| G-003 | 视频转写产物以标准 Markdown+YAML front matter 写入 `raw/`，**下游五阶段管道零改动** | [PM推断:依据]最小侵入原则 |
| G-004 | 全链路使用 `deepseek-v4-flash` 模型 | [用户原话]硬约束 1 |
| G-005 | 第⑦棒只产出空文件骨架，第⑧棒真实模拟运行（8~15 拍端到端） | [用户原话]硬约束 2 & 3 |
| G-006 | RA 调研阶段用 research-tool 真实运行 ≥4 次，逐条验证 PRD 假设 | [用户原话]硬约束 5 |

## 6. 验收标准（每条 P0/P1 ≥1 条可执行验证）

> 完整验收标准已嵌入第 3 章每条功能的"验收标准"列。下列为端到端级别的总体验收（必跑）：

### 6.1 端到端必跑（V1.0 准入）

1. **AC-E2E-01**：给定 B 站公开带字幕视频（`https://www.bilibili.com/video/BVxxxxxxxxx`），`research run "demo" --video-url <url>` 在 8 分钟内产出 `reports/demo.md`，报告含视频 front matter 与至少 3 章节正文。

3. **AC-E2E-03**：同一 URL 第二次入参，3 秒内返回缓存并打印 `[cache hit]`。
4. **AC-E2E-04**：模拟非法 URL（`https://example.com/notvideo`），CLI 在 1 秒内返回错误码 E_DL_001 并打印"现象+原因+下一步"。
5. **AC-E2E-05**：模拟 Whisper 不可用（环境移除），CLI 返回错误码 E_TR_001，中间产物保留在 `cache/video/<id>.partial/`。
6. **AC-E2E-06**：审计日志，100% LLM 调用 `model = "deepseek-v4-flash"`。
7. **AC-E2E-07**：RA 真实跑 4+ 次 research-tool 用例（含竞品/技术/方案/风险四类），全部假设逐条核对，PRD 修订建议增量回写。

> 满足 [用户原话]硬约束 4：明确哪些模块从 BiliNote 移植、哪些在 research-tool 内新建、接口契约如何对齐。

| 模块 | 来源 | 代码量估算 | 接口契约 |
|------|------|-----------|----------|
| `downloader.bilibili` | 移植 BiliNote `BiliDownloader` | 移植 ~800 行 | `download(url, cookie) -> Path` |
| `downloader.youtube` | 移植 BiliNote `YTDLPWrapper` | 移植 ~300 行 | `download(url, cookie) -> Path` |
| `transcriber.whisper` | 移植 BiliNote `FastWhisperTranscriber` | 移植 ~600 行 | `transcribe(audio_path) -> List[Segment]` |
| `transcriber.bcut` | 移植 BiliNote `BcutTranscriber` | 移植 ~400 行 | `transcribe(audio_path) -> List[Segment]` |
| `transcriber.subtitle` | 移植 BiliNote `BilibiliSubtitleFetcher` | 移植 ~200 行 | `fetch_subtitle(url) -> Optional[List[Segment]]` |
| `llm_client` | **新建**（research-tool 侧） | 新建 ~400 行 | 替换 BiliNote 的 SQLite 配置为 `.env`，强制 model=deepseek-v4-flash |
| `video_ingestor` | **新建** | 新建 ~500 行 | 编排 downloader→transcriber→llm 的串行流 |
| `pipeline_adapter` | **新建** | 新建 ~250 行 | 将视频产物落 `raw/<topic>/<video-id>.md` 触发既有管道 |
| `cache_manager` | **新建** | 新建 ~300 行 | URL hash → Markdown 路径，含过期与失效 |
| `cli_bindings` | **新建** | 新建 ~300 行 | 解析 `--video-url` / `--video-file` / `--cookie-file` 等 |
| `notes_schema` | **新建** | 新建 ~150 行 | 定义 video front matter 的 YAML 字段集 |
| BiliNote 前端/桌面 | **不移植** | — | B-005 锁定 |
| BiliNote 任务队列/DB | **不移植** | — | B-005 锁定 |

**移植比例**：约 60% 代码（downloader + transcriber 主体）；**新建比例**：约 40%（适配与编排）。**接口契约核心**：
1. `transcribe` 返回统一 `List[Segment] {start, end, text}`；
2. `notes_schema` 字段集为 `video_id / source_url / title / author / duration / cover_url / tags / chapters[] / created_at`；
3. 既有五阶段管道 **零修改**，仅在 Collect 阶段新增"raw/ 下发现 video_*.md 即纳入"1 行配置。
