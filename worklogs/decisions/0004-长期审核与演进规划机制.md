# ADR 0004: 长期审核与演进规划机制

> **日期**: 2026-07-21
> **状态**: 已采纳
> **决策者**: 人（基于 Phase 0 审核产出）

## 背景

research-tool 项目（v0.1.1 + R12 阶段）已具备 11 个 FP、454 测试、26 错误码、3 ADR，但缺少长期演进规划机制：

- 现状技术债（含 P0 安全 / 可移植 / CI）散落在 STATUS.md
- Star 增长瓶颈（gh api 实测 stars=0）无系统化改进路径
- 创新点未经过诚实性验证

## 决策

在项目根新建 `project_management/` 长期看板，结构：

```
project_management/
├── status/         # 当前进度（current_status.md + milestone_status.md）
├── worklog/        # 工作日志（YYYY-MM-DD-task.md）
├── decisions/      # ADR 候选
├── problems/       # code_quality.md + technical_debt.md
├── experiments/    # 实验设计 + 验证报告
├── reports/        # 8 份审核报告 + 4 份 roadmap + final_report.html
├── innovation/     # 9 创新点 catalog
└── archive/        # deleted_files/ 登记（不实际删除）
```

复用 research-tool 自身的模板（`docs/templates/worklog模板.md` 等），不引入新模板语言。

## 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| `project_management/`（采纳） | 长期演进看板；不暗示一次性 audit | 命名不直观 |
| `audit/` | 直白说明用途 | 暗示一次性，与"长期整理"目标不符 |
| 复用 `docs/` | 风格一致 | 与已有 `docs/{plan,reports,templates}` 角色冲突 |

## 影响

- 8 个 Phase 各自有 DoD 校验，无产出物不进入下一 Phase
- 矛盾点用 `grep`/`cat`/`pytest --collect-only` 实证解决
- 所有 P0/P1/P2 债务有路径 + 行号 + 命令证据
- 实验若未跑通，强制 UNVERIFIED 标记 + 诚实性报告
- 审计期 `git status` 必须与启动期一致（无未授权修改）

## 后果

- 每次收束节点（Round X）后应更新 `current_status.md`
- 新增 P0/P1/P2 债务必须同步到 `STATUS.md`（仅追加）
- 本机制不替代 `STATUS.md`；后者仍是项目权威
